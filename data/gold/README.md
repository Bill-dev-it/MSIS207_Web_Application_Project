# Gold Layer — Application-Ready Data

The Gold layer contains **application-ready seed data** produced from cleaned
Silver datasets and controlled demo data.

Its purpose is to transform heterogeneous aviation and e-commerce data into
records that match the PostgreSQL application schema.

```text
Silver Data
     │
     ▼
Transform + Map + Integrate
     │
     ├── Source-derived data
     ├── Transformed data
     └── Controlled demo data
     │
     ▼
Gold Application Tables
     │
     ▼
PostgreSQL
```

## Gold Dataset

The current pipeline generates **10 seed tables**:

| Table | Purpose |
|---|---|
| `companies` | Buyer and supplier organizations |
| `addresses` | Company addresses |
| `categories` | Aviation part categories |
| `engine_models` | Aircraft engine model reference |
| `suppliers` | Marketplace suppliers |
| `aircraft` | Demo buyer aircraft fleet |
| `engines` | Engines assigned to aircraft |
| `products` | Aviation spare parts |
| `seller_listings` | Supplier price, stock and commercial offers |
| `product_engine_compatibility` | Demo mapping between parts and compatible engines |

These tables provide the initial reference and marketplace data required by the
application.

Runtime tables such as users, carts, orders, payments, shipments, reviews and
RUL predictions are **not artificially populated by this pipeline**. They are
created by the application or AI service during system operation.

---

## Data Provenance

Gold data is not assumed to come entirely from real-world sources.

**Source-derived data** includes reference information such as FAA
manufacturer and engine model data and spare-part metadata from the source
datasets.

**Controlled demo data** is used where the available datasets do not provide
the complete relationships required by the application. This includes demo
company identities, addresses, fleet assignments, commercial offers and
engine-part compatibility mappings.

Price values use a project-defined markup rule, while inventory quantities are
synthetically generated for marketplace simulation.

All generated compatibility relationships are explicitly treated as
**demo compatibility**, rather than verified real-world aviation compatibility.

Relevant source metadata and demo indicators are preserved where applicable,
including in `products.technical_specs`.

## Build Process

Gold CSV files are generated by:

```bash
python data/scripts/silver_to_gold/build_gold.py
```

The generator follows the current DBML database schema and produces the files
deterministically. Re-running the pipeline with the same inputs produces the
same output.

Manual modification of generated Gold CSV files is discouraged. Changes should
instead be made in the transformation/generation logic.

---

## PostgreSQL Loading

Gold data should be loaded into an empty application schema in the following
dependency order:

```text
companies
   ↓
addresses
   ↓
categories
   ↓
engine_models
   ↓
suppliers
   ↓
aircraft
   ↓
engines
   ↓
products
   ↓
seller_listings
   ↓
product_engine_compatibility
```

CSV files use UTF-8 with headers. Empty nullable values should be mapped to
`NULL`, explicit IDs should be preserved, and PostgreSQL identity sequences
should be advanced after import.

> The current data pipeline generates and validates Gold data only.
> Loading the generated data into PostgreSQL is handled separately.

---

## Validation

Validate the generated Gold layer with:

```bash
python data/scripts/silver_to_gold/build_gold.py --check
```

Validation checks that the generated data conforms to the application schema,
including required fields, data types, uniqueness rules, foreign-key
relationships and relevant constraints.
